## Scope and evidence

The implementation audited was `src/SSH/Key/Install-SSHPublicKey.ps1`.
At that time it had no repository callers. `devops.ps1` and the original SSH tests
loaded a different function from the then-existing `src/SSH/SSHKeyInstall.ps1`,
with different parameters and a setup workflow that created the alias after
installation. T09.4 left that workflow unchanged; the later menu migration
replaced it. The other Key/Connection functions were inspected without changes.

The original command generated this quoting structure:

```text
sh -c "eval "$(printf '%s' '<script-base64>' | base64 -d)"" sh '<key-base64>'
```

The inner double quote terminates the outer quoted argument. The decoded script
is consequently subject to splitting by the login shell before `sh -c` runs.
Running the actual generated command locally with Git Bash reproduced an inner
`BASH_EXECUTION_STRING='eval set'`, a dump of shell variables ending in
`_=/usr/bin/sh`, exit 0, and no installation status marker. `set` without
arguments prints shell variables. This directly explains the earlier unexpected
server response; it is evidence of command construction failure, not connectivity
failure. The Windows native argument parser adds another quoting boundary, so
shell-only syntax validation cannot establish that the original transport works.

The original source also encoded its CRLF here-string without normalization.
The replacement explicitly normalizes LF. Git Bash accepted CRLF in the local
probe, so CRLF is a portability concern, not a locally proven cause of exit 2.
No Ubuntu reproduction was performed: the exact server-side source of the
reported exit 2 remains unverified. The original generic exception omitted the
diagnostics needed to distinguish syntax errors from remote utility failures.

Other confirmed defects in the inspected code:

- `grep -Fq` searches substrings anywhere, including comments and longer blobs.
- `set -- $public_key` splits and expands shell patterns in comments unnecessarily.
- Native stderr was not included in the thrown failure.
- Windows PowerShell 5.1 with `ErrorActionPreference=Stop` can terminate on native
  stderr before exit-code handling. The new native executable test reproduced
  this with exit 255; the implementation now handles it explicitly.

## Implementation

The public entry point keeps `-Alias` and `-PublicKeyPath` and returns `Alias`,
`PublicKeyPath`, `Status`, and `Success`. Status is `INSTALLED` or
`ALREADY_INSTALLED`; failures throw.

Only a selected `.pub` file is read. One public key line is required and
`ssh-keygen -l -f` validates its material. ED25519, RSA, and the standard NIST
ECDSA algorithms are accepted. Comments are discarded before transport.
No private-key partner is opened or derived. OpenSSH itself performs normal
authentication, including any private-key/passphrase handling it needs.

The command sent to the alias is a single argument:

```text
printf '%s' '<script-base64>' | base64 -d | sh -s
```

The script includes only Base64-encoded, validated public material. Its LF UTF-8
payload avoids embedded double quotes at the Windows argument boundary, shell
expansion of input data, `eval`, `sh -c`, positional parameters, and PowerShell
stdin encoding. `sh -s` consumes the decoded script through remote stdin.
If the outer decoder fails and the last pipeline command exits zero, the missing
status marker still makes the client fail rather than report success.

The script refuses symbolic links and nonregular paths, uses umask 077, creates
missing paths, and applies modes 700 and 600. It appends only, with a leading
newline to preserve unterminated existing entries. Its awk scanner compares the
algorithm and blob exactly in the key fields, allowing one options field with
quoted spaces and escaped quotes. It never searches arbitrary comments. Existing
options/restrictions and existing bytes remain intact. An awk failure terminates
the script instead of being treated as a missing key.

Errors retain the native exit code, stdout, stderr, and a remote operation label
where available. Exactly one status marker must appear on stdout; startup banners
are tolerated, conflicting markers rejected, and stderr markers cannot establish
success. Successful calls surface stderr as a warning. A temporary diagnostics
file is removed in `finally`, and the caller's error preference is preserved.

## Manual Ubuntu acceptance

Use an existing alias and an intended public key on an account you authorize
for installation. Replace `ubuntu-dev` and the public path as needed. These
commands append the selected key and apply directory/file permissions; they
do not replace config or keys. Normal SSH fingerprint verification remains active.

```powershell
. ./src/SSH/Key/Install-SSHPublicKey.ps1
$sshAlias = 'ubuntu-dev'
$publicPath = Join-Path $HOME '.ssh/id_ed25519.pub'

# Confirm alias resolution and account before installation.
ssh -G $sshAlias
ssh -T $sshAlias whoami
if ($LASTEXITCODE -ne 0) { throw 'SSH account check failed' }

$first = Install-SSHPublicKey -Alias $sshAlias -PublicKeyPath $publicPath -Verbose
$first | Format-List
# Expected: INSTALLED, or ALREADY_INSTALLED if present already.

$beforeRepeat = @(ssh -T $sshAlias 'sha256sum ~/.ssh/authorized_keys')
if ($LASTEXITCODE -ne 0) { throw 'Cannot hash authorized_keys' }
$second = Install-SSHPublicKey -Alias $sshAlias -PublicKeyPath $publicPath
if ($second.Status -ne 'ALREADY_INSTALLED') { throw 'Repeat installation was not idempotent' }
$afterRepeat = @(ssh -T $sshAlias 'sha256sum ~/.ssh/authorized_keys')
if ($LASTEXITCODE -ne 0) { throw 'Cannot hash authorized_keys' }
if (($beforeRepeat -join "`n") -cne ($afterRepeat -join "`n")) {
    throw 'authorized_keys changed during the repeated installation'
}

# Expected modes: 700 followed by 600; then public fingerprints.
ssh -T $sshAlias 'stat -c %a ~/.ssh ~/.ssh/authorized_keys; ssh-keygen -lf ~/.ssh/authorized_keys'
if ($LASTEXITCODE -ne 0) { throw 'Remote inspection failed' }

# Verify authentication with passwords disabled; encrypted keys may prompt.
ssh -T -o PreferredAuthentications=publickey -o PasswordAuthentication=no -o KbdInteractiveAuthentication=no $sshAlias whoami
if ($LASTEXITCODE -ne 0) { throw 'Public-key authentication failed' }
```

The last command verifies an available configured key. To isolate the selected
key's identity, add `-o IdentitiesOnly=yes -i <matching-private-key-path>` to
that manual SSH command. The installer never needs that private path.

## Remaining limits

- Live Ubuntu shell behavior, ownership/ACLs and actual mode enforcement need the
  acceptance commands above; Git Bash on NTFS cannot establish Linux permissions.
- PowerShell 7 compatibility is intended but unverified. The native test recorder
  uses Windows PowerShell's .NET Framework executable compiler.
- Installation is sequential. Concurrent installers or another process editing
  the same file can race the duplicate/path checks. This assumes a trusted HOME
  owned by the remote account, not an adversary replacing paths mid-operation.
- Existing authorized-key options are preserved, not interpreted for whether they
  allow interactive login. This avoids adding an unrestricted copy of a restricted key.
- `.pub` selection is required; unsupported/certificate/security-key algorithms
  are rejected. No locking, backup system, alias migration, or legacy CLI rewrite
  was added for this task.
